# Ice 2 v3.0.0: a smaller Ice for macOS 27

Status: agreed, 2026-11-07. Supersedes the 2.x layout model for macOS 27 and later.

## Why

macOS 27 draws every menu bar item into one MenuBarAgent window, so the 2.x design (one window per
item, moved and captured individually) cannot work there. 2.16 bypassed this with a native backend
bolted onto the 2.x app. 3.0.0 keeps that proven backend and drops everything that depended on the
old model, so the app does a few things and does them well.

## Scope

- Runs on macOS 27 and later only. 2.x remains the release for macOS 26 and earlier.
- Same app: still named **Ice 2**, same repository, same bundle identifier
  (`com.dragonapp.ice`), delivered to 2.x users on macOS 27 as an ordinary Sparkle update.
  Version starts at **3.0.0**.
- Rewritten rather than migrated. Everything not listed below is removed: Always-Hidden, hotkeys,
  layout profiles, spacers, search, menu bar appearance, auto-rehide, icon choices, the
  MenuBarItemService helper.

## Terms

- **Item**: one entry in the menu bar that Ice can hide. On macOS 27 hiding works per process, so
  an item is a whole app (`bundle:<bundle id>`, all of its icons together) or a supported system
  item (`system:<n>`: Battery, Bluetooth, Displays, Keyboard, Sound, Wi-Fi, Screen Mirroring).
- **Show / Hide**: the one setting per item. Hidden items are hidden in the real menu bar.
- **Ice Bar**: the panel under the Ice icon that lists the hidden items.
- **Order**: one list of item ids, shared by the Ice Bar and the Settings list.

## Behaviour

### Ice icon

- One status item drawn with the Dot image (filled). No icon choice.
- Shown or hidden by General ▸ *Show in menu bar*, live. Hiding it also closes the Ice Bar. When Ice
  starts with the icon hidden (and Accessibility granted), Settings opens on General so the user
  can turn it back on; reopening the app from Finder also opens Settings.
- Left-click toggles the Ice Bar. Right-click opens DragonKit's `DragonAppMenu`
  (About Ice 2, Check for Updates…, Settings…, Quit Ice 2).

### Ice Bar

- A non-activating glass panel (`NSPanel` + `NSGlassEffectView` hosting SwiftUI) placed just under
  the menu bar, centred on the Ice icon. macOS 27 reports a status item's window frame as zero, so
  the anchor is the click location on the icon, clamped to the screen.
- Shows each hidden item whose app is running (a system item always), in Order: the app's icon for an app, an SF Symbol for a system item.
- Drag an icon onto another to take its place; this changes the shared Order.
- Click an icon: Ice adds that item to the allowed set (it reappears in about 65 ms), sends
  `AXPress` to its button in MenuBarAgent's accessibility tree, and closes the Ice Bar. The app's own
  menu opens at the item's real place in the menu bar. When that menu closes (or after a timeout),
  Ice hides the item again.
- Closes on a second click of the icon, a click anywhere else (including Ice's own windows), or Escape.
- Ice cannot change the real menu bar order (only Command-drag can), so Settings suggests
  Command-dragging hidden apps next to the Ice icon so their menus open nearby.

### Items and hiding

- Discovery walks MenuBarAgent's accessibility tree (bounded traversal, timeouts) on launch, when
  running apps change, and every 15 seconds.
- New items start as **Show**. A hidden item whose app quits stays listed (under its last name) so it
  can be shown again; a shown one leaves the list but keeps its place in the Order for when it returns.
- The clock, Control Center and unmapped system items cannot be hidden on macOS 27 and are not
  listed. Ice never lists itself.
- Hiding uses a runtime-loaded `MenuBarClientCore` assessment-mode assertion whose allowed set is
  every running app except hidden ones, plus every supported system item not hidden.
- Fail open: if the framework is missing, Accessibility is not granted, activation fails or times
  out, the assertion is released and everything shows. Quit and sleep release it; wake re-applies.

### Settings (DragonKit)

Pane order (DragonKit canon): **General → Permissions → Backup & Restore → What's New → Updates →
About → Uninstall**.

- **General**
  - *Startup*: Launch at login.
  - *Language*: the eight Dragon languages (see below).
  - *Menu Bar*: Show in menu bar (on by default). Note below: while the Ice icon is hidden the Ice
    Bar can't be opened and hidden items stay hidden; if Ice 2 starts with the icon hidden,
    Settings opens so the user can turn it back on.
  - *Menu Bar Items*: one row per item (drag handle, icon, name, Show/Hide segmented control), in
    Order, draggable. Note below: hidden items wait in the Ice Bar; click the Ice icon to open it;
    drag to change the order; the Command-drag tip.
- **Permissions**: Accessibility (DragonKit `PermissionsSettingsPane`).
- **Backup & Restore**: DragonKit's pane. A backup holds every setting: Launch at login, the
  language, Show in menu bar, Show or Hide for each item, and the Order. The pane lists these under
  "A backup saves" through DragonKit's `BackupConfig.contents` (added in DragonKit for this release). Any setting added later
  joins both the backup and that list.
- What's New, Updates, About, Uninstall: DragonKit panes. Uninstall also removes the settings suite.
- *Language*: DragonKit's `LanguagePicker` with the eight languages every Dragon app ships.

### Storage

All settings live in one `DragonSettingsStore` suite (`<bundle id>.settings`), as one Codable value:
`launchAtLogin`, `language` (DragonKit's choice copied here, since the kit keeps the live value
outside the suite; a stored value wins at launch, and with none stored the current one is kept),
`showInMenuBar` (default true; a stored value without the key, such as one saved by an earlier 3.0
build or an older backup, loads as true), `hidden` (set of item ids), `order` (item ids), `names`
(last seen display name per id, so absent apps stay readable). Backup & Restore snapshots that suite.

### Upgrade from 2.x

On first launch of 3.x, if the 3.x value is absent, read 2.x's `NativeMenuBarSections`
(`[id: "visible" | "hidden" | "alwaysHidden"]`) from the standard defaults: visible becomes Show,
hidden and alwaysHidden become Hide. The Order starts as hidden items first (in their saved order
where known), then the rest. 2.x's "Show Ice 2 icon" (Bool `ShowIceIcon` in the same defaults)
becomes Show in menu bar, so a user who hid the icon in 2.x starts with it hidden; this applies even
when there are no `NativeMenuBarSections`. Every other 2.x setting is ignored. 2.x defaults are
left in place; a language chosen in 2.x is kept.

### Distribution

- `LSMinimumSystemVersion` is 27.0. Sparkle's `generate_appcast` copies it into the appcast's
  `sparkle:minimumSystemVersion`, so 2.x on macOS 26 or earlier is never offered 3.0.0.
- `MACOSX_DEPLOYMENT_TARGET` stays 26.0 because release CI builds with the macOS 26 SDK; no
  macOS 27 SDK API is used.

## Testing

- Unit tests (pure logic, no menu bar): item identity and policy, merging discovered items with
  saved state (new items Show, absent items kept, Ice excluded), Order operations, assertion
  configuration for the normal and reveal states, 2.x migration, settings Codable round trip,
  backup contents list matching the stored keys.
- Manual, on macOS 27 with Accessibility granted: hide and show, Ice Bar placement, click to open an
  app's menu and rehide, reorder in both places, quit restores items, backup and restore.

## Out of scope

Multiple displays beyond the main menu bar, per-icon hiding within one app, any restyling of the
menu bar, and macOS 26 or earlier.
